# Shared middleware

Per-system Traefik files (`wikijs-<slug>.yml`) reference a middleware called `wikijs-forwarded-headers@file`. That middleware lives in a separate **shared file** that's created once and used by every system.

## Why a separate file

The middleware sets `X-Forwarded-Proto: https` so Wiki.js generates correct absolute URLs when it sees only HTTP from Traefik. Every system needs this — duplicating it across files would mean changing N files when the middleware ever needs updating.

The legacy `wikijs.yml` (managing `prohat.topminds.se` etc.) already defines this middleware. But that file is owned by the operator, may be removed or renamed, and isn't a stable foundation for per-system files.

The skill ensures a `wikijs-shared.yml` exists in `<TRAEFIK_DYNAMIC_CONFIG_DIR>` before writing any per-system file. If `wikijs.yml` already defines the same middleware name, Traefik logs a duplicate warning but takes the most recently loaded definition. Both are functionally identical, so no harm.

## File location

```
<TRAEFIK_DYNAMIC_CONFIG_DIR>\wikijs-shared.yml
```

On DOCKERHOST1: `C:\projects\traefik\dynamic\wikijs-shared.yml`.

## Generated content

```yaml
# Generated by system-docs-domain skill — do not edit by hand.
# Shared Traefik middleware used by all wikijs-<slug>.yml files.
#
# This file is created on first use of the system-docs-domain skill and
# left alone on subsequent runs. Delete it only if you also delete every
# wikijs-<slug>.yml that references it.

http:
  middlewares:
    wikijs-forwarded-headers:
      headers:
        customRequestHeaders:
          X-Forwarded-Proto: "https"
```

## When it's created

`configure_domain.py add` checks for the file. If absent, it writes it. If present, it leaves it alone — the file is owned by the platform, not by individual systems.

The check is path-based, not content-based: if you've manually edited `wikijs-shared.yml` to add other shared middlewares, the skill won't overwrite your changes.

## When to delete it

When the last system that uses it is removed. The skill doesn't delete it automatically, because:

- Other manually-configured Traefik files might reference the same middleware
- It's a small file with no cost to keep

If you want to clean up:

```powershell
# After removing all per-system files:
Remove-Item C:\projects\traefik\dynamic\wikijs-shared.yml
```

## Coexistence with `wikijs.yml`

The legacy file `C:\projects\traefik\dynamic\wikijs.yml` defines the same middleware. Traefik's behaviour with duplicates:

- It loads both files
- The router definition that's loaded last wins (alphabetical by filename, so `wikijs-shared.yml` after `wikijs.yml`)
- Logs a `WARN` about the duplicate
- Functionality is unaffected since both definitions are identical

To keep things clean, eventually move the middleware definition out of `wikijs.yml` into `wikijs-shared.yml` and remove the duplicate from `wikijs.yml`. But this is not required for the skill to work.
